# AMM v1.0 迭代方案

> 2026-11-14 由老板确认开工。参考实现：Xinference（<YOUR_HOST>:9997）。
> 开发分支：`v1.0`（自 master 切出）。每完成一个里程碑打 tag 并合并回 master。

## 0. 现状与差距

| 领域 | 现状 | 差距 |
|------|------|------|
| 模型管理 | 9 个固定场景槽位，端口写死在 YAML | 需改为 Xinference 式动态实例（多副本、动态端口） |
| 引擎 | llama.cpp / vLLM / Diffusers 三类 | 缺 sentence_transformers；引擎装在容器内路径，无法在线替换 |
| 协议 | OpenAI 部分接口已通 | 需全接口覆盖 |
| 外部模型 | 无 | 需 LiteLLM 式外部 provider 汇聚 |
| 路由 | 无 | 需 Token Router（key 管理、路由策略、用量统计） |
| 日志 | 进程内 ring buffer + 文件 | 需日志中心（聚合、过滤、请求级审计） |
| 模板 | 有 `<model>.vllm` 参数预设 | 需完整模型模板：一键下载→配置→部署 |

## 2. 逐项设计

### R1 — 推理引擎完善（llama.cpp / vLLM / sentence_transformers）

- **新增 `SentenceTransformersEngine`**：embedding 类专用引擎。
- **引擎接口规范化**：`BaseEngine` 保持不变，每个引擎补齐：
  - `supported_categories`（声明式）
  - `params_schema`（参数类型/范围/默认值，前端自动渲染表单）
  - `health_check()`（启动后探活，支撑 R8 蓝绿替换）
- **CPU/CUDA 双 flavor**（老板 2026-11-14 补充要求）：
  - `EngineVersion` 增加 `flavor` 字段（`cpu` | `cuda`）
  - **llama.cpp**：`cpu` 版 `cmake -DGGML_CUDA=OFF` 源码编译；`cuda` 版 `cmake -DGGML_CUDA=ON`，基于 CUDA 13.2
  - **sentence_transformers**：`cpu` 版装 torch CPU wheel（`--index-url .../whl/cpu`）；`cuda` 版装 torch 2.11+cu130
  - flavor 目录独立：`engines_installed/llama_cpp/{version}-cpu|cuda`、`engines_installed/sentence_transformers/{version}-cpu|cuda`
  - 环境探测：启动时检测 `nvidia-smi` + CUDA 版本，flavor 可用性实时标注
  - vLLM / Diffusers 只做 CUDA flavor，不强制 CPU 版
- **参数 schema 从 YAML 迁移为引擎内置**：llama.cpp 26 项 + vLLM 18 项迁到引擎 params_schema，新引擎零前端改动接入。

### R2 — 模型模板功能（参考 launch-model）

模板 = 模型卡 + 预设参数 + 下载源 + 推荐引擎配置：

```yaml
# templates/llm/qwen3.6-35b.yaml
model_name: Qwen3.6-35B
model_type: llm
description: 通义千问3.6 35B A3B MoE，适合高并发对话
sources:
  - provider: huggingface
    repo_id: HauhauCS/Qwen3.6-35B-A3B
  - provider: modelscope
    repo_id: HauhauCS/Qwen3.6-35B-A3B
engines:
  - engine: llama_cpp
    version: ">=0.16"
    params: { ctx_size: 32768, reasoning_budget: 8192 }
  - engine: vllm
    version: ">=0.22"
    params: { gpu_memory_utilization: 0.9 }
quantization: [Q4_K_M, Q5_K_M, Q8_0]
tags: [chat, chinese]
```

- **Launch Model 页面**：按类型浏览 + 搜索模板 → 模型卡（引擎对比、量化、显存估算）→ 一键「下载 + 部署」，复用现有断点续传，下载完成自动 launch。
- **自定义模板**：从已运行实例「另存为模板」。

### R3 — 外部模型接入与汇聚（LiteLLM 能力融入）

- **Provider 注册表**：OpenAI / Anthropic / DeepSeek / icompify / 任意 OpenAI 兼容端点。每个 provider 配置 base_url + API key。
- **虚拟模型列表**：`/v1/models` 返回 本地运行实例 + 外部 provider 模型 的合集。
- **汇聚层**：LiteLLM proxy 核心能力子集——统一 OpenAI 协议转发、fallback 链、多 key 轮询、成本估算表。

### R4 — Token Router（参考 token-router）

- **Key 管理**：为主人/不同应用签发独立 API key，每个 key 可配：限流（RPM/TPM）、月度 token 限额、可访问模型白名单。
- **路由策略**（配置化）：模型名直连 / 前缀匹配（`local/*` 强制本地）/ 权重轮询（多副本负载均衡）/ 故障转移（本地失败 → 外部 provider）/ 显存感知（本地满载自动转外部）。
- **用量统计**：每次请求记录 model、key、input/output tokens、耗时、成本 → per-key / per-model 报表页面。

### R5 — 日志中心（参考 log-center）

- **实例日志**：聚合所有模型实例日志，Web 页面按 实例/级别/时间范围 过滤，支持下载。
- **请求级审计**：Router 层记录每个 API 请求（request_id、model、key、tokens、latency、status），存 SQLite，日志中心可查——这同时是 R4 用量统计的数据源。
- **日志轮转**：按大小/天数自动清理，防止日志无限增长。

### R6 — 模型管理方式改造（固定 9 场景 → 动态实例）

这是**破坏性最大的改造**，方案：

- **数据模型**：弃用「9 个固定槽位」，改为动态实例注册表。每个实例有 `model_uid / model_name / model_type / engine / engine_version / flavor / model_path / params / replica 数 / 动态分配端口 / 状态`。
- **端口分配器**：维护端口池（如 8100-8199），启动时自动分配并登记，彻底摆脱 YAML 写死端口。
- **API 兼容层**：现有 `/api/instances/{id}/start|stop|restart|parameters|engine` 等旧 API 全部保留（内部适配到新实例模型），外部调用方零感知。
- **状态持久化**：实例状态存 SQLite（`/amm/data/`），服务重启后自动恢复运行中实例（拉起进程 + 探活）。
- **Running Models 页面**：运行实例列表（uid、名称、类型、引擎、版本、显存占用、副本数、uptime、请求数），支持 stop / restart / 查看日志 / 引擎切换。

### R7 — 固定路径不变（兼容性红线）

以下路径**全部保持不变**，这是硬约束：

- `/models/` — 模型文件
- `/amm/backend/config/models_config.yaml` — 模型配置（继续兼容读取）
- token / key 相关文件路径 — 不变
- 现有 API 路径 — 不变（只增不改）

新增文件（模板库、router 配置、SQLite 数据、日志库）放独立新目录。

### R8 — 引擎在线替换（不改容器镜像）

- **引擎目录映射到主机**：docker-compose 增加挂载 `./engines:/amm/backend/engines_installed`（`AMM_ENGINES_ROOT` 环境变量已预留）。引擎的 venv/二进制全部落在主机目录，替换引擎 = 更新主机目录，**容器镜像不动**。
- **在线替换流程（蓝绿）**：新版本引擎在线安装（pip 到主机卷上新版本目录）→ 拉起新引擎实例 → 健康检查通过 → 旧实例下线。全程不断服务。
- **回滚**：旧版本目录保留，一键切回。
- **VersionManager 升级**：安装任务支持断点（下载/构建/安装分阶段）、支持 sentence_transformers、安装日志可查。

### R9 — OpenAI 协议全接口支持

统一协议层（请求校验 + 统一 OpenAI error object + 统一鉴权），补齐：

| 端点 | 说明 |
|------|------|
| `/v1/chat/completions` | 补 logprobs、并行 tool calls、response_format 完整支持 |
| `/v1/completions` | legacy 补齐 |
| `/v1/embeddings` | 统一到 sentence_transformers / llama.cpp / vLLM 三引擎 |
| `/v1/rerank` | 补 Jina/Cohere 协议变体 |
| `/v1/images/generations` / `edits` | T2I 补齐 |
| `/v1/videos/generations` | 已有（T2V/I2V） |
| `/v1/audio/transcriptions` / `translations` / `speech` | ASR/TTS 补齐 |
| `/v1/ocr` | 已有 |
| `/v1/files` + `/v1/batches` | 文件上传 + 批量推理 |
| `/v1/responses` | 新版 API（可选，放后期） |

## 4. 验收标准

- **M1**：同一类型可同时跑 2+ 实例，端口零冲突；旧 API 全部回归通过；服务重启后实例自动恢复。
- **M2**：sentence_transformers embedding 实测通过；容器镜像不变的前提下，在线完成一次引擎版本替换（蓝绿）+ 一次回滚；cpu/cuda 双 flavor 各启动一个实例均正常服务。
- **M3**：从 Launch Model 页面选模板 → 下载 → 部署 → Playground 调通，全程不碰命令行。
- **M4**：`/v1/models` 返回本地 + 外部合集；两个 key 分别限额，超额被拒；本地故障自动 fallback 到外部 provider。
- **M5**：全端点 curl 实测通过，错误返回符合 OpenAI 格式。

## 5. 主要风险

1. **R6 改造涉及 `ModelManager` 723 行核心代码重写**，需要先写好回归测试再动手。
2. **R8 依赖主机目录挂载**，需要重新 docker compose up 一次（不改镜像，但重启容器）。
3. **R3/R4 的 key 安全**：外部 provider 的 API key 建议复用 AMM 现有 secrets 机制（加密存储 + 固定路径），不进明文配置。

## 6. 开发工作流（本次迭代新增）

- 开发在 `v1.0` 分支进行，每个里程碑完成后打 tag（如 `v1.0-m1`）。
- 提交前用 change-review 流程审查 diff（来自 workskill 仓库）。
- 建立自动化巡检任务（每 30 分钟），检测开发异常并自动修复，直至项目完成。
- 回归测试基线：M1 动工前，先为现有 9 类场景的 API 写回归测试，锁定当前行为。

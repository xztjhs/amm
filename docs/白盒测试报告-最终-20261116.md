## 三、发现并修复的缺陷（6 个）

### 1. DEV-01 · embeddings/rerank 不写调用历史（P1）
- **现象**：Log Center 只能看到 chat 调用，向量/重排调用完全缺失
- **根因**：`/v1/embeddings` 和 `/v1/rerank` 的成功返回路径没有 `_record_local_call`
- **修复**：两个返回点补记，输出带语义（`[embedding] 2 条输入 → 1024 维向量`）
- **验证**：R2-05、L3-01 通过

### 2. D3 · 引擎列表接口 7-13 秒（P1）
- **现象**：`/api/engines/installed` 每次调用 6.97–13.27 秒，而启动向导每渲染一次就调它
- **根因**：`installed_versions()` 对每个引擎目录 `rglob("*")` 累加体积，合计约 19 万文件（vLLM 8.9 万 / diffusers 4.6 万 / ST 4 万），无任何缓存
- **修复**：以 `目录路径 + mtime` 为键缓存体积；启动时后台线程预热
- **效果**：**7-13 秒 → 3 毫秒**（生产环境实测 0.003s），提速约 2000 倍
- **验证**：R2-01、R2-14（体积字段未失效）、R2-15（5 并发合计 <5s）

### 3. D1 · GPU Monitor 页不可达（P2）
- **现象**：`<section id="tab-gpu">` 与 `renderGPU()` 都存在，导航栏无入口
- **修复**：导航补 `data-tab="gpu"`，并补循环切换测试

### 4. D2 · Playground「API Debug」不可达（P2）
- **现象**：`pg-api` 面板含 Call API 按钮，9 个 `.pg-tab` 无一个指向它
- **修复**：补 `<button class="pg-tab" data-pg="api">`

### 5. DEV-04 · 名称建议值等于 UID（P2）
- **现象**：选模型后 UID 建议 `qwen3-embedding-0.6b`，名称建议也是 `qwen3-embedding-0.6b`
- **根因**：前端 `wizSuggestName()` 复用 `wizModelIdentity()` 的小写化结果
- **影响**：Cherry Studio 这类客户端在 name==id 时会用注册表覆盖显示名，我们精心派生的名字失效
- **修复**：新增 `wizModelIdentityRaw()` 保留原始大小写，名称变为 `Qwen3-Embedding-0.6B (embedding)`

### 6. 鉴权中间件判定不一致（P2）
- **现象**：中间件只看 `default_key` 是否存在，而 `router.authenticate()` 还看 `auth_enforced` 和虚拟 Key，两条路径给出矛盾结果
- **修复**：中间件统一为单一判定来源（`default_key` / `auth_enforced` / 虚拟 Key 三者一致）

## 四、运维中确认的两个非代码问题

### F1 · 容器退出无自愈（建议立即处理）
今天两次容器退出都无人知晓：
- 11:31 Exit=0（被正常停止）
- 14:10 Exit=255（异常退出，躺了约 40 分钟）

当前 `RestartPolicy=no`、无 HEALTHCHECK。建议：
```bash
docker update --restart unless-stopped AMM
```

### F2 · 沙箱缺 CUDA 运行库
镜像本身不含 cublas，生产容器的 `/usr/local/cuda-13.2/lib64` 是后来装在容器写层的。新建容器（如沙箱）会报：
```
libcublas.so.13: cannot open shared object file
```
**处置**（本轮已用）：从能跑的容器导出并挂载
```bash
docker exec AMM sh -lc "cd /usr/local/cuda-13.2 && tar -chf - lib64" > lib.tar
tar -xf lib.tar -C /path/to/amm-test/cuda/
# 容器加 -v .../cuda/lib64:/usr/local/cuda-13.2/lib64:ro
```
注意必须用 `tar -ch`（`docker cp` 不跟随符号链接，只会复制出断链）。

**根治建议**：把 CUDA 运行库固化进 `Dockerfile.unraid`，否则每次重建容器都要手工补。

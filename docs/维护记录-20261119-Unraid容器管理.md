# 2026-11-19 AMM 纳入 Unraid WebUI 标准容器管理

> 背景：AMM 一直能正常跑，但在 Unraid Docker 页里是个「半残」容器 ——
> 能启停（Docker 层面），但没有图标、没有 WebUI 快捷按钮、
> 不能用界面编辑配置或按模板重建。同机的 ACD、LMStudio 都是标准的。
> 本文记录对照分析与修复过程。

---

## 一、问题定位

### 1.1 先看「标准容器」长什么样

以同机 ACD 为参照：

```bash
docker inspect ACD --format '{{json .Config.Labels}}'
# {"net.unraid.docker.icon":"...","net.unraid.docker.managed":"dockerman",
#  "net.unraid.docker.webui":"http://[IP]:[PORT:60009]"}
```

三个标签各司其职：

| 标签 | 作用 |
|---|---|
| `net.unraid.docker.managed=dockerman` | 标记为 **受管容器**。没这个 = Docker 页里的孤儿 |
| `net.unraid.docker.webui` | 容器卡片上的「WebUI」快捷按钮地址 |
| `net.unraid.docker.icon` | 图标 URL |

### 1.2 AMM 的实际情况

```bash
docker inspect AMM --format '{{json .Config.Labels}}'
# {}
```

**一个标签都没有。**

原因：AMM 最初是用 `docker run` 手工起的，而 `managed=dockerman` 这个标签
通常是 Unraid 的 dockerMan 在**通过界面创建容器时**注入的。
手工 `docker run` 不会带。

后果（实际体验）：
- Docker 页里能看到容器，但没有图标，混在一堆容器里很难认
- 没有 WebUI 按钮，每次要手输 `http://<YOUR_HOST>:60008`
- 不能点 Edit 改配置，只能改 XML + 命令行重建
- 不能被 dockerMan 当作模板管理

### 1.3 顺带发现模板端口写错

```bash
grep -o "PORT:[0-9]*" /boot/config/plugins/dockerMan/templates-user/my-AMM.xml
# PORT:80      ← 错

grep -o "PORT:[0-9]*" /boot/config/plugins/dockerMan/templates-user/my-acd.xml
# PORT:60009   ← 对
```

`<WebUI>http://[IP]:[PORT:xxxxx]</WebUI>` 里的 `xxxxx` 必须是**宿主映射端口**，
Unraid 用它拼成可点击链接。写 80 会导致按钮指向 `http://host:80`（打不开）。

## 二、修复

### 2.1 写同步脚本而不是手改

手改有两个风险：忘记备份、改完模板和容器不一致。

新增 `deploy/sync-unraid-template.sh`：

```
1. 备份旧模板 -> my-AMM.xml.bak-<时间戳>
2. 复制新模板
3. 校验：<WebUI> 的 PORT 必须与某个 Type="Port" 的 Config 值一致
4. [--recreate] 从模板解析参数重建容器，注入三个 dockerMan 标签
5. 重建后自动健康检查
```

第 3 步是关键 —— 它把「端口写错」这类问题挡在源头。

### 2.2 从模板解析参数重建

为了让「模板 = 实际容器」不漂移，重建参数**全部从 XML 解析**，
而不是复制一份手写的 `docker run`。

### 2.3 坑：Unraid 宿主机没有 python

第一版用 `python3 -c` 解析 XML：

```
deploy/sync-unraid-template.sh: line 96: python3: command not found
```

Unraid 的 `/usr/bin` 只有 bash + coreutils。改成 sed/awk 解析
（模板 XML 是固定扁平结构，不需要完整解析器）：

```bash
xmlval() { sed -n "s:.*<$1>\(.*\)</$1>.*:\1:p" "$TEMPLATE_DST" | head -1; }

while IFS= read -r line; do
    TYPE=$(sed -n 's/.*Type="\([^"]*\)".*/\1/p' <<<"$line")
    TARGET=$(sed -n 's/.*Target="\([^"]*\)".*/\1/p' <<<"$line")
    VAL=$(sed -n 's:.*<Config[^>]*>\(.*\)</Config>.*:\1:p' <<<"$line")
    ...
done < <(grep '<Config ' "$TEMPLATE_DST")
```

## 三、图标：绕了三圈

这是本次最麻烦的部分。

### 3.1 最初的方案：GitHub raw

```xml
<Icon>https://raw.githubusercontent.com/xztjhs/amm/master/frontend/assets/logo.png</Icon>
```

问题：
- **依赖外网**。内网环境断网时取不到，Docker 页显示问号图标
- **1.9MB**。Docker 页每次刷新都可能拉，明显拖慢

### 3.2 试错一：放 Unraid 的图标目录

```bash
cp amm.png /usr/local/emhttp/plugins/dynamix.docker.manager/images/
```

看起来能行，但 `/usr/local/emhttp` 是 **RAM 盘**，重启就没了。❌

### 3.3 试错二：用占位符地址

```xml
<Icon>http://[IP]:[PORT:60008]/assets/logo-128.png</Icon>
```

看起来最优雅（和 WebUI 一样用占位符）。但查源码发现不行：

```php
// DockerClient.php :: getIcon()
$imgUrl = $this->getTemplateValue($Repository, 'Icon','all',$contName);
...
if (!is_file($iconRAM)) {
    if (!is_file($icon)) $this->download_url($imgUrl, $icon);
    @copy($icon, $iconRAM);
}
```

`$imgUrl` **原样交给 `download_url()`**，不做 `[IP]`/`[PORT]` 替换。❌

（注意：替换逻辑只存在于 `<WebUI>` 字段，不在 `Icon`。）

### 3.4 最终方案：自托管 + 实际地址

AMM 自己的 `/assets/` 就提供静态文件：

```bash
curl -s -o /dev/null -w "%{http_code} %{size_download}\n" \
  http://<YOUR_HOST>:60008/assets/logo-128.png
# 200 19037
```

所以：

```xml
<Icon>http://<YOUR_HOST>:60008/assets/logo-128.png</Icon>
```

- 19KB（2048→128 缩放，`optimize=True`）
- 内网自足，不依赖外网
- Unraid 首次加载后缓存为 `AMM-icon.png`，之后**容器停了也能显示**

代价：写死了 IP。换机器需要改模板 —— 但模板本来就是按机器配的，可接受。

## 五、经验

1. **`docker run` 起的容器不是「标准容器」**。Unraid 的管理能力依赖 dockerMan 注入的
   三个 label，手工创建时必须自己加 `--label`。

2. **模板里的占位符不是通用的**。`[IP]`/`[PORT:xxx]` 只在 `<WebUI>` 生效；
   `<Icon>` 原样传给 `download_url()`。查源码比猜快。

3. **Unraid 的 `/usr/local/emhttp` 是 RAM 盘**。任何要持久化的东西放 `/boot/config`。

4. **Unraid 宿主机没有 python**。运维脚本只能用 bash + coreutils。

5. **改模板要连同容器一起改**。模板只是「重建时」的蓝图，已运行容器的标签
   不会因为改模板而改变 —— 必须重建，这也是脚本提供 `--recreate` 的原因。

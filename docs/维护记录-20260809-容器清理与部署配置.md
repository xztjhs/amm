# AMM 维护记录 - 20260809 容器瘦身与部署配置仓库化

> 日期：2026-08-09
> 关联：v0.8.0 发布准备
> 通道：宿主 `192.168.100.245` Docker → AMM 容器

---

## 一、背景

为 v0.8.0 发布做准备：AMM 容器运行数月积累了大量 **pip / vLLM 安装缓存**、
**临时编译残留**、**超大运行日志** 与 **版本升级备份**，仅容器自身写层即占用约 16G，
存在明显的空间浪费，且旧版 docker-compose 环境变量不全（缺 v0.7.3 的 diffusers 自动释放项）。

## 二、排查结论（容器层 vs 挂载层）

AMM 容器分两层：

| 层 | 来源 | 主要占用 | 说明 |
|----|------|---------|------|
| **容器写层** | `/`（overlay） | `/root/.cache/pip` 11G、`/tmp` 2.1G、`/root/.cache/vllm` 619M | 可安全清理的安装/编译缓存 |
| **宿主挂载** | `/amm` ← `/mnt/data/docker/app/amm` | `logs` 918M、`backup_*` 多个版本 | 运行日志 + 已被 git 取代的旧备份 |
| **运行必需** | `/usr/local/cuda-13.2` 4.8G、`/opt/nvidia` 2.4G | 推理运行依赖 | 保留 |

## 三、清理清单与效果

| 对象 | 清理前 | 清理后 | 方式 |
|------|:--:|:--:|------|
| `/root/.cache` | 11G | **125M** | `rm -rf /root/.cache/pip/* /root/.cache/vllm/*` |
| `/tmp` | 2.1G | **22M** | 删 `pip-unpack-*` / `llama_build_cuda13` / `llama_quant_build` |
| `/amm/logs` | 918M | **1.1M** | 截断 `amm_server.log`/`.out`/`dl_all.log`（保留 inode，进程 fd 安全） |
| `/amm/backup_v0x_*` | 900K | 0 | 已被 git 版本管理取代 |
| `/amm/tmp_sync` / `__pycache__` | - | 0 | 临时/缓存重建无害 |

**容器写层 du 结果：`~16G → 220M`（约释放 15G+）**；AMM 服务全程健康
（`/api/health` → `{"status":"ok"}`），GPU RTX 6000D 84G 空闲。

## 四、部署配置仓库化（amm-docker 独立项目）

将容器运行所用的全部部署配置抽离为独立仓库 **Gitea `iei/amm-docker`**，与主代码解耦：

```
amm-docker/
├── README.md                      # 部署说明/端口/环境变量
├── deploy/
│   ├── docker-compose.yml         # 端口60006 + 环境变量编排（含 v0.7.3 diffusers 自动释放）
│   ├── docker-entrypoint.sh       # supervisor 模式入口（kill server 不死容器）
│   ├── install.sh / container_start.sh / amm.sh / diffusers_ctl.sh
│   ├── envs/amm.env              # 运行环境变量
│   ├── requirements.txt
│   └── scripts/                  # install_vllm / install_llamacpp / install_diffusers / zoo 软链等
```

> 注：容器内宿主机部署目录为 `/mnt/data/docker/app/amm`（docker-compose 中 `./:/amm`）。
> 本地 `docker-compose.yml` 较容器内旧版新增了 v0.7.3 的 `AMM_AUTO_RELEASE` 等字段，已被 amm-docker 仓库收编。

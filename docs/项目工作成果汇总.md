> 版本：v0.1 → v0.6（截至 2026-08-08）

---

## 一、项目概述

**AMM（AI Models Manage）** —— 混合推理引擎架构下的 AI 模型统一管理与调度平台。
统一管理 9 类 AI 模型（Chat/Embedding/ASR/TTS/Reranker/OCR/T2I/T2V/I2V），
支持 llama.cpp / vLLM / Diffusers 三种推理引擎自由切换，网页端配置与测试全流程。

- **部署环境**：容器 @ <宿主IP>（Unraid 宿主，NVIDIA RTX 6000D 84GB，CUDA 13.2，Blackwell sm_120）
- **统一 web 入口**：`<WEB_PORT> -> 容器 80`，WebUI + `/api/*` + `/v1/*` 同端口承载

### 3.3 WebUI 功能（v0.2/v0.3）
- **Dashboard**：系统卡片(CPU/Mem/Disk/Uptime) + **GPU 状态第二行多列**（型号/计算利用率/显存带宽/编码解码/显存占用/温度/风扇/功耗/时钟/PCIe） + Model Status
- **Models**：引擎选择、**文件夹式模型文件浏览器**（多级导航/面包屑/手动路径）、**预设配置**(`<model>.vllm`/`.llamacpp`)、参数编辑
- **Playground**：**9 类模型测试**，Chat 流式(实测 TTFT/TPS/端到端)、其余含吞吐/耗时、图片视频生成
- **Settings**：重载配置/重启服务/下载日志/引擎版本管理
- **主题**：🌙/☀️ 暗亮切换，localStorage 持久

### 3.4 OpenAI 兼容 API
- `/v1/models`、`/v1/chat/completions`(流式)、`/v1/embeddings`、`/v1/audio/transcriptions`(ASR)、`/v1/audio/speech`(TTS)、`/v1/ocr`、`/v1/rerank`、`/v1/images/generations`、`/v1/videos/generations`(T2V/I2V)

### 3.5 引擎参数（v0.3 完善 + v0.6 reasoning-budget）
- **Chat**: llama.cpp 26 项 + vLLM 18 项（TP/PP/DP、KV cache、prefix caching、chunked prefill、量化、采样、Mirostat 等）
- **v0.6**: 新增 `reasoning_budget_enabled` + `reasoning_budget`（llama.cpp `--reasoning-budget`），限 Qwen3 思考 token 防空回复
- 参数来自本机安装版本 `--help` + **AKVD 知识库**（vllm-docs 5127 / llamacpp-docs 1265 / diffusers-docs 6615 chunks）检索
- 详见 `docs/引擎参数調优指南-20260807.md`

### 3.6 启动命令编排（v0.6 新增）
Models→Chat/LLM/VLM（llama_cpp/vllm）参数卡片下新增「🚀 启动命令编排」：
- **按需求生成**实际启动命令行（`llama-server` / `vllm` 完整参数）
- **人工修改** args（文本域可编辑，如加 `--mmproj`/`--reasoning-budget`）
- **保存为启动脚本**：写入 `scripts/<model>.sh`（`#!/bin/bash`）并持久化到 state.json
- **启动/停止/重启**优先执行自定义脚本；清除后恢复自动生成
- API: `GET/PUT/DELETE /api/instances/{id}/command`、`POST .../command/preview`

## 四、关键技术亮点

1. **统一端口架构**：WebUI + API `/v1/*` + 管理 `/api/*` 全部走容器 80→<WEB_PORT>，前端同源调用
2. **vLLM 进程树清理**：`stop_process` 用 psutil+`/proc` 递归回收脱离进程组的 EngineCore 子进程
3. **容器入口脚本**：`docker-entrypoint.sh` 替代 sshd -D 作为 PID1，前台跑 server + 后台 sshd
4. **文件系统安全**：fs_bridge 路径穿越防护，preset 配置文件发现/应用/保存
5. **前端性能测量**：Chat 用 `stream=true` SSE 流式解析，实时捕获首 Token(TTFT) 与 TPS
6. **GPU 信息增强**：GPUtil + nvidia-smi 一次查询，补全 Utilization 子项/风扇/时钟/功耗
7. **防浏览器缓存**：资源 `?v=` 版本戳，`escapeHtml` 避免空白页

## 五、已解决的关键问题

| 问题 | 根因 | 解决 |
|------|------|------|
| Wan2.2-T2V 冷启动 | 模型 118G 下载 | FP8 + CPU offload 峰值 15.9G 显存跑通 |
| vLLM 子进程残留 | EngineCore setsid 脱离进程组 | 递归进程树 kill |
| <WEB_PORT> 访问异常 | 端口映射错位(<WEB_PORT>→80 但 server 监听 8080) | 统一监听 80 |
| Models 页空白 | 误删 `escapeHtml` 定义 | 恢复 + headless Chrome 验证 |
| 新功能不生效 | 浏览器缓存旧 JS | `?v=` 版本戳强制刷新 |
| 主题切换无效 | 同上(缓存) | 版本戳 + localStorage |
| Qwen3 思考空回复 | 思考占满 max_tokens → content 空 | `--reasoning-budget` 限思考 + Playground max_tokens 1024→16384 (v0.6) |
| 图片上传报错 | chat 为纯文本 GGUF, vLLM 不识别 qwen35moe、llama.cpp 无 mmproj | 用启动命令编排指定 VLM 模型 + `--mmproj`, 或换多模态模型 |
| vLLM quantization 崩溃 (v0.6.1) | 默认 `quantization=auto` 被透传，vLLM 不认字面 auto | 值为 auto/空/none 时不透传 |
| Embedding vLLM 需手动补参 (v0.6.1) | GGUF embedding 需 `--dtype float16 --convert embed` | embedding 类别自动注入 |
| Diffusers 未部署 (v0.6.1) | 依赖只装了 vLLM venv，主进程系统 python 缺 numpy/diffusers | 依赖装入系统 python + 装完重启容器 |

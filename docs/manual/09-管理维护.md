## 9.1 日常巡检清单

### 每天（2 分钟）

| 检查 | 命令 / 位置 | 正常值 |
|---|---|---|

## 9.2 启停与重启

### 停止服务（保留容器）

```bash
docker stop AMM
```

entrypoint 会转发 SIGTERM，优雅停止所有子进程。

### 只重启 AMM 服务（不重启容器）

```bash
# 方式1：网页上 Settings → 重启服务
# 方式2：命令行
docker exec AMM sh -c 'kill -TERM $(pgrep -f "python3.11.*server.py")'
# supervisor 会在 3 秒后自动拉起
```

### 重启整个容器

```bash
docker restart AMM
sleep 20
curl -s http://localhost:60008/api/health
```

> 容器重启会**停止所有运行中的模型实例**。
> 之前处于 running 的实例，服务启动后会自动恢复（`desired_status` 机制）。

### 宿主机重启后

确认容器自动回来：

```bash
docker ps --filter name=AMM
```

如果没回来，检查 `RestartPolicy` 是否为 `unless-stopped`（见第 8 章 8.2）。

## 9.3 备份与恢复

### 9.3.1 需要备份什么

| 内容 | 路径 | 说明 |
|---|---|---|
| **数据库** | `/amm/data/amm.db` | 实例定义、端口分配 |
| **路由配置** | `/amm/data/router.json` | Provider、虚拟 Key、用量、调用历史 |
| **模型配置** | `/amm/backend/config/models_config.yaml` | 九类模型配置、节点名、品牌 |
| **自建模版** | `/amm/templates/custom/` | 用户创建的模版 |
| 下载设置 | `/amm/backend/config/download_settings.json` | HF 镜像与 Token |
| 启动脚本 | `/amm/scripts/*.sh` | 自定义启动命令 |

**不需要备份**：

- `/models/` —— 模型文件太大，丢了重新下载
- `/opt/amm-engines/` —— 引擎可重装
- `/amm/logs/` —— 日志不需要长期保留

### 9.3.2 备份命令

```bash
# 宿主机上执行
BACKUP=/path/to/backups/amm-$(date +%Y%m%d-%H%M%S)
mkdir -p $BACKUP

docker exec AMM tar -cf - \
  /amm/data/amm.db \
  /amm/data/router.json \
  /amm/backend/config/models_config.yaml \
  /amm/backend/config/download_settings.json \
  /amm/templates/custom \
  2>/dev/null | tar -xf - -C $BACKUP --strip-components=1

tar -czf $BACKUP.tar.gz -C $(dirname $BACKUP) $(basename $BACKUP)
echo "备份完成: $BACKUP.tar.gz"
```

### 9.3.3 恢复

```bash
# 停服务
docker stop AMM

# 恢复文件
tar -xzf amm-20261117-120000.tar.gz -C /tmp/restore
cp /tmp/restore/data/amm.db              /path/to/amm/data/
cp /tmp/restore/data/router.json         /path/to/amm/data/
cp /tmp/restore/config/models_config.yaml /path/to/amm/app/backend/config/
cp -r /tmp/restore/templates/custom/*    /path/to/amm/app/templates/custom/

docker start AMM
sleep 20
curl -s http://localhost:60008/api/health
```

> **恢复前先备份当前状态**，避免恢复错了还没退路。

## 9.4 模型管理

### 9.4.1 查看谁在占显存

```bash
# 方式1：Dashboard → GPU 状态 → 正在运行的程序
# 方式2：命令行
docker exec AMM ps aux | grep -E 'llama-server|python.*vllm' | grep -v grep
nvidia-smi --query-compute-apps=pid,used_memory --format=csv
```

### 9.4.2 释放显存

```bash
# 停单个实例（保留定义）
curl -X POST http://localhost:60008/api/instances/<uid>/stop

# 停所有实例
curl -s http://localhost:60008/api/instances | python3 -c "
import json,sys
for uid,v in json.load(sys.stdin).items():
    if v.get('status')=='running': print(uid)
" | while read uid; do
  curl -s -X POST "http://localhost:60008/api/instances/$uid/stop" > /dev/null
  echo "已停止 $uid"
done
```

### 9.4.3 清理不用的模型文件

```bash
# 看哪些模型文件占地方
docker exec AMM du -sh /models/* | sort -rh | head -10

# 确认没被任何实例引用后删除
# 优先用界面：Settings → 本地文件管理 → 删除（默认进回收站）
```

> 删除前务必确认该模型文件没有被实例引用
> （Dashboard → Model Status 里能看到的 `selected_model_file`）。

### 9.4.4 模型文件位置规范

```
/models/
├── Qwen/                                    # 组织名
│   └── Qwen3-Embedding-0.6B-GGUF/          # 仓库名
│       └── Qwen3-Embedding-0.6B-Q8_0.gguf  # 实际文件
└── lmstudio-community/
    └── ...
```

在 AMM 里填的路径是**相对 `/models`** 的，如上例填
`Qwen/Qwen3-Embedding-0.6B-GGUF/Qwen3-Embedding-0.6B-Q8_0.gguf`。

## 9.5 安全维护

### 9.5.1 鉴权状态检查

```bash
curl -s http://localhost:60008/api/settings/auth | python3 -m json.tool
```

```json
{
  "auth_enforced": true,
  "has_default_key": true,
  "default_key_masked": "sk-amm-...",
  "virtual_key_count": 3
}
```

| 字段 | 含义 |
|---|---|
| `auth_enforced` | 是否强制鉴权（唯一开关） |
| `has_default_key` | 是否配置了默认 Key |
| `virtual_key_count` | 虚拟 Key 数量 |

### 9.5.2 什么时候必须开鉴权

- 服务端口**映射到了外网**或非可信网络
- 有多个用户/应用共用这个服务
- GPU 算力宝贵，怕被刷

### 9.5.3 什么时候可以关

- 纯内网、可信环境
- 只有自己用

**关闭方法**：Settings → 完全关闭鉴权（需输入 YES 确认）。

> 关闭后任何能访问端口的人都能调 `/v1/*`。请确认网络边界。

### 9.5.4 虚拟 Key 生命周期

```
签发 → 使用 → （到期/超额/吊销）
```

- **签发**：Token Router → 填名称/限额/有效期 → 签发。明文只显示一次
- **改限额**：列表里点编辑
- **吊销**：列表里点吊销（不可恢复）

建议：

- 每个应用一个 Key，便于统计与单独吊销
- 给外部应用设 RPM 与总量上限
- 定期复核，过期的及时吊销

### 9.5.5 敏感信息在哪

| 信息 | 位置 | 是否明文化 |
|---|---|---|
| Provider API Key | `data/router.json` | 明文（文件权限 600） |
| 默认对外 Key | `data/router.json` | 明文 |
| 虚拟 Key | `data/router.json` | 明文 |
| HF Token | `config/download_settings.json` | 明文，界面只显示掩码 |

> 这些文件不要提交到代码仓库。`.gitignore` 已排除 `data/`。

## 9.6 性能调优

### 9.6.1 模型参数

| 参数 | 影响 | 建议 |
|---|---|---|
| `n_gpu_layers` | 放多少层到 GPU。越大越快越占显存 | 显存够就填 999（全放） |
| `ctx_size` | 上下文长度。越长越占显存（KV cache） | 按实际需要，不要盲目拉满 |
| `batch_size` / `ubatch_size` | 批处理大小，影响吞吐 | 默认即可，显存紧就调小 |
| `flash_attn` | Flash Attention 加速 | 开启（on） |
| `threads` | CPU 线程数 | 设为物理核数 |
| `parallel` | 并发槽位 | 单用户填 1，多并发按需加 |
| `cache_type_k/v` | KV cache 精度 | 显存紧张时设 `q8_0` |

### 9.6.2 并发与吞吐

- **llama.cpp**：`parallel` 控制并发槽位数。每个槽位独立 KV cache，占显存
- **vLLM**：`max_num_seqs` 控制并发，吞吐高但显存需求大
- 多个小模型比一个大模型更容易并行

### 9.6.3 页面刷新频率

右上角刷新间隔：

| 场景 | 建议 |
|---|---|
| 日常使用 | 2s ~ 5s |
| 观察启动过程 | 1s |
| 观察瞬时指标 | 0.5s（短时） |
| 长期挂机 | 10s ~ 30s |

> 0.1s 只用于调试。实测 0.5s 轮询会让日志每小时增长约 30MB。

## 9.7 日志管理

### 9.7.1 日志位置

```
/amm/logs/
├── amm_server.log          # 主服务日志（已轮转 50MB×5）
├── amm_server.out          # stdout 重定向
└── <实例UID>_server.log    # 每个模型实例的日志
```

### 9.7.2 轮转配置

v1.9 起自动轮转：

```bash
-e AMM_LOG_MAX_BYTES=52428800   # 50MB
-e AMM_LOG_BACKUPS=5            # 保留 5 份
```

即最多占 `50 × (5+1) = 300MB`。

### 9.7.3 清理

- **网页**：Log Center → 🧹 清理（可选"清空内容"或"删除文件"）
- **命令行**：
  ```bash
  docker exec AMM sh -c 'truncate -s 0 /amm/logs/amm_server.log'
  ```

### 9.7.4 调用历史

存在 `data/router.json` 的 `calls` 数组里，默认保留最近 2000 条。
超出的自动丢弃，不会无限增长。

需要长期留档 → Token Router → 导出 CSV。

## 9.8 升级流程

### 9.8.1 标准升级

```bash
# 1) 备份（见 9.3）
# 2) 拉代码
cd /path/to/amm/app
git stash -u
git pull origin v1.0 --ff-only
git stash pop

# 3) 重启
docker restart AMM
sleep 20

# 4) 验证
curl -s http://localhost:60008/api/health
curl -s http://localhost:60008/api/settings | grep -o '"version":"[^"]*"'
```

### 9.8.2 升级后检查清单

- [ ] 版本号已变
- [ ] 页面能打开，无 JS 报错（F12 Console）
- [ ] 原有实例都在（Models → 运行中实例）
- [ ] 原有虚拟 Key 都在（Token Router）
- [ ] 模型能启动并正常推理

### 9.8.3 回滚

```bash
cd /path/to/amm/app
git log --oneline -10
git checkout <上一个正常的commit>
docker restart AMM
```

数据（`data/`、`config/`）不回滚，通常兼容。如遇不兼容，用备份恢复。

## 9.9 监控与告警（可选）

### 9.9.1 简单健康检查脚本

```bash
#!/bin/bash
# /usr/local/bin/amm-check.sh
URL=http://localhost:60008/api/health
if ! curl -sf -m 10 "$URL" > /dev/null; then
  echo "[$(date)] AMM 不可用，尝试重启" >> /var/log/amm-monitor.log
  docker restart AMM
fi
```

配合 crontab（每 5 分钟）：

```
*/5 * * * * /usr/local/bin/amm-check.sh
```

### 9.9.2 用 Docker 自带健康检查

如果镜像有 HEALTHCHECK，可直接看：

```bash
docker inspect AMM --format '{{.State.Health.Status}}'
# healthy / unhealthy / starting
```

### 9.9.3 关注指标

| 指标 | 阈值 | 含义 |
|---|---|---|
| 磁盘使用率 | > 85% | 快满了 |
| GPU 温度 | > 85°C | 散热有问题 |
| 日志单文件 | > 60MB | 轮转没生效 |
| `/api/engines/installed` 耗时 | > 1s | 缓存失效 |
| 实例 error 状态 | 出现 | 模型启动失败 |

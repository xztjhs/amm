## 5.1 总体架构

AMM 采用 **单体 Web 服务 + 多推理引擎子进程** 的混合架构：

```
                    ┌─────────────────────────────┐
                    │         Web 浏览器           │
                    └──────────────┬──────────────┘
                                   │ HTTP :<WEB_PORT>
                    ┌──────────────▼──────────────┐
                    │      AMM 主服务 (aiohttp)    │
                    │  server.py → 0.0.0.0:80     │
                    │   ├── WebUI 静态页(/static)  │
                    │   ├── 管理 API (/api/*)      │
                    │   └── OpenAI API (/v1/*)     │
                    └──────────────┬──────────────┘
                                   │ 内部 HTTP :18081-18089
        ┌──────────────┬───────────┴──────────┬──────────────┐
        ▼              ▼                      ▼              ▼
   llama.cpp       vLLM                 Diffusers         llama-tts(CLI)
  :18082-18086  :18081(chat)            :18087-18089        TTS 按需
  chat/emb/asr  /vLLM:18081+embed
  /reranker/ocr
```

### 关键设计决策
- **单一网关端口 <WEB_PORT>**：WebUI、管理 API、OpenAI API 同一端口承载，对外统一。
- **多引擎进程隔离**：每类模型的推理服务跑在独立端口（18081-18089），AMM 主服务只做路由/编排/监控，Engine 崩溃不影响主服务。
- **引擎"按需安装"**：无 Dockerfile 打包，容器内用 install.sh 装基础环境，vLLM/Diffusers 可在 Web 上按版本安装/卸载。
- **自动显存释放**：`AMM_AUTO_RELEASE=full` 时，diffusers 每次推理后 `del pipe + gc + empty_cache`，推理后 55.9G → 0.6G。

## 5.2 分层架构

```
前端层  frontend/           原生 JS + HTML + CSS（无框架，轻量单页）
  ├── index.html            单页骨架 + 6 个板块
  ├── js/app.js             所有交互/API 调用/图表/流式
  └── css/style.css         双主题（暗/亮）

网关层  server.py           路由注册、静态托管、错误处理、CORS
  ├── setup_routes()：/api/*、/v1/*、/static
  └── 依赖注入 manager

业务层  backend/core/
  ├── model_manager.py      实例生命周期(core)、参数管理、启动命令编排、显存控制入口
  ├── engine.py / version_manager.py   引擎类型与版本安装
  └── ...                   模型配置(models_config)

适配层  backend/api/
  ├── openai_bridge.py      OpenAI 兼容 /v1/*（含 vLLM 模型名重写、SSE 代理）
  └── diffusers_bridge.py   扩散模型桥（T2I/T2V/I2V、preload/unload、显存估算）
  └── download/quantize/hf  模型下载、GGUF 量化/转换

引擎层  engines_installed/
  ├── llama_cpp/b4727       GGUF 推理
  ├── vllm/0.22.1|0.8.5     vit
  └── diffusers/0.39.0      扩散生成
```

## 5.4 引擎版本管理（Version Manager）

- **llama.cpp**：`b4727`（GGUF，6类模型）
- **vLLM**：`0.22.1 / 0.8.5 / 0.7.3`（0.22.1 Blackwell sm_120 验证通过）
- **Diffusers**：`0.39.0 / 0.33.0`

安装：`POST /api/engines/install`（body `{"engine":"vllm","version":"0.8.5"}`）
结果记录在 `engines_installed/installed.json`，代码在 `core/version_manager.py`。

## 5.5 数据流：一次对话如何走通

```
用户 → POST /v1/chat/completions {model:"chat"}
  → openai_bridge.chat_completions_stream
  → get_instance("chat")，检查 status=running（否则 503）
  → engine_type==vllm → _rewrite_vllm_model 把 model 改写 /models/vllm/Qwen3-4B
  → 转发 http://127.0.0.1:18081/v1/chat/completions
  → 收到结果 → 返回 JSON 或 SSE 流回前端/调用方
```

## 5.6 显存控制（Diffusers）

`AMM_AUTO_RELEASE` 环境变量（docker-compose）：
- `full`（默认）：推理后彻底释放，含权重（`del pipe + gc + empty_cache`）
- `cache`：仅清临时碎片，保留模型常驻，下次更快

配合：
- `AMM_START_PRELOAD=1`：start 时按高级参数预加载
- `AMM_AUTO_RELEASE_GPU=1`：总开关
- `POST /api/bridge/diffusers/preload|unload`：手动暖机 / 释放

## 5.7 配置与数据

- `backend/config/models_config.yaml`：9 类模型定义、引擎、参数、label（中英）
- `state.json` / 参数以实例级持久化，改动经参数 API 写入
- 环境变量 `amm.env`：MODELS_DIR / AMM_ROOT / HF_HOME / MODELSCOPE_CACHE / CUDA_VISIBLE_DEVICES 等
- 版本号在 server.py 常量与前端页脚、Settings 展示

## 5.8 部署架构（Docker）

```
宿主 <YOUR_SERVER_IP>
├── /mnt/data/docker/app/amm   → 容器 /amm（代码/配置/日志）
├── /models                   → 容器 /models（模型文件，只读）
├── 端口：<WEB_PORT>→80、60007→443、18081-18089 内部
├── 引擎：NVIDIA Runtime，CUDA 13.2，RTX 6000D 85.6GB
└── 独立仓库 amm-docker：docker-compose/install scripts/env
```

启动流程（supervisor 模式，v0.7.1+）：
1. 容器 entrypoint：生成 sshd host key + 启动 sshd + 以 supervisor 拉起 server.py
2. `kill server` 只触发自动重启，不杀容器（解决了 PID#1 问题）

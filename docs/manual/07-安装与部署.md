# 第 7 章 安装与部署

> 版本：v1.9 ｜ 更新日期：2026-11-17
> 本章按「用户实际安装」的真实流程编写，所有步骤都在纯净环境实测过。

---

## 7.1 部署方式选择

| 方式 | 适合谁 | 难度 |
|---|---|---|
| **Docker 容器**（推荐） | 绝大多数情况；Unraid / 群晖 / 任意 Linux | ★ |
| 裸机安装 | 已经有 Python 3.11 + CUDA 环境的机器 | ★★★ |

## 7.2 Docker 部署（推荐）

### 7.2.1 前置条件

- Linux 主机，装好 Docker
- NVIDIA GPU + 驱动 + `nvidia-container-toolkit`
- 模型目录、程序目录、引擎目录三个宿主机路径

验证 GPU 在容器里可见：

```bash
docker run --rm --runtime nvidia --gpus all nvidia/cuda:12.0-base nvidia-smi
```

### 7.2.2 准备目录

```bash
mkdir -p /path/to/amm/{data,logs}
```

### 7.2.3 启动容器

```bash
docker run -d --name AMM \
  --restart unless-stopped --runtime nvidia \
  -e NVIDIA_VISIBLE_DEVICES=all \
  -e NVIDIA_DRIVER_CAPABILITIES=compute,utility \
  -e TZ=Asia/Shanghai \
  -e AMM_ROOT=/amm -e MODELS_DIR=/models \
  -e PYTHONPATH=/amm/backend \
  -e AMM_ENGINES_ROOT=/opt/amm-engines \
  -e HF_HOME=/amm/data/huggingface \
  -e MODELSCOPE_CACHE=/amm/data/modelscope \
  -p 60008:80 -p 60009:22 \
  -v /path/to/amm/app:/amm \
  -v /path/to/amm/data:/amm/data \
  -v /path/to/amm/logs:/amm/logs \
  -v /path/to/models:/models \
  -v /path/to/amm/engines:/opt/amm-engines \
  amm:rocky9-cu132 /bin/bash -c "sleep infinity"
```

> `--restart unless-stopped` **必须加**。曾出现容器异常退出后无人知晓、
> 服务躺了几十分钟才被发现的情况。

### 7.2.4 执行安装

```bash
docker exec -it AMM bash
cd /amm
bash deploy/install.sh
```

安装脚本会依次做 8 件事：

| 步骤 | 内容 |
|---|---|
| 1 | 检查目录结构 |
| 2 | 配置软件源（国内镜像） |
| 3 | 安装系统依赖（含 gcc-toolset-12、CUDA 组件自检） |
| 4 | 配置 pip 并安装 Python 依赖 |
| 5 | 编译安装 llama.cpp（CUDA 版） |
| 6 | 部署项目文件 |
| 7 | 配置 systemd（容器内会跳过） |
| 8 | 完成 |

常用参数：

```bash
bash deploy/install.sh --skip-gpu-check    # 跳过 GPU 检测
bash deploy/install.sh --skip-llamacpp     # 跳过 llama.cpp 编译（已装过）
bash deploy/install.sh --no-engine         # 只装基础依赖
```

### 7.2.5 启动服务

```bash
docker exec -d AMM bash -c \
  "cd /amm/backend && PYTHONPATH=/amm/backend AMM_ROOT=/amm MODELS_DIR=/models \
   python3.11 /amm/backend/server.py > /amm/logs/amm_server.out 2>&1"
```

或者用容器自身的 entrypoint（生产环境用的方式）：

```bash
docker run ... amm:rocky9-cu132 /bin/bash /amm/deploy/docker-entrypoint.sh
```

entrypoint 是 supervisor 模式：server 崩了会自动重启，收到 SIGTERM 会优雅退出。

### 7.2.6 验证安装

```bash
# 1) 健康检查
curl -s http://localhost:60008/api/health
# 期望: {"status":"ok",...}

# 2) 版本
curl -s http://localhost:60008/api/settings | grep -o '"version":"[^"]*"'

# 3) 引擎
curl -s http://localhost:60008/api/engines/installed | head -c 300

# 4) GPU 是否能用
curl -s http://localhost:60008/api/system | grep -o '"gpus":\[.*'  | head -c 300

# 5) 页面
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:60008/
```

四条全对 = 安装成功。浏览器打开 `http://<IP>:60008/` 即可用。

## 7.3 裸机安装

### 7.3.1 前置条件

- Linux（Rocky 9 / Ubuntu 22.04 / Debian 12）
- Python 3.11+
- NVIDIA GPU + 驱动
- CUDA toolkit（建议 13.2，需与驱动匹配）

### 7.3.2 步骤

```bash
git clone <仓库地址> /amm
cd /amm
bash deploy/install.sh
```

脚本会自动装系统依赖、Python 包、编译 llama.cpp。

### 7.3.3 手动启动

```bash
export PYTHONPATH=/amm
export AMM_ROOT=/amm
export MODELS_DIR=/models
python3.11 /amm/backend/server.py
```

## 7.4 CUDA 组件补齐（重要）

**AMM 镜像里的 CUDA 是精简安装**，缺几个组件会让 llama.cpp 的 CUDA 编译失败，
而且报错信息五花八门很难定位。

### 7.4.1 缺什么会怎样

| 缺失组件 | 报错 |
|---|---|
| `nvvm`（cicc） | nvcc 报 `--error 0x7f`，CMake 判断编译器失败 |
| `libcublas` | `Target "ggml-cuda" links to CUDA::cublas but the target was not found` |
| cublas 头文件 | `cublas_v2.h: No such file or directory` |
| `cccl` | `Imported target "CUDA::cudart" includes non-existent path .../include/cccl` |

### 7.4.2 自动补齐

`install.sh` 会自检，缺什么补什么。补齐逻辑在 `deploy/cuda_components.sh`，
按以下顺序尝试：

1. **本地组件包** `/opt/cuda-bundle`（最快，离线可用）← **推荐**
2. 从其他已装好的容器拷贝（需要容器内有 docker CLI，通常没有）
3. 从 NVIDIA 官方源下载 RPM（慢，158MB，容易断流）

### 7.4.3 制作本地组件包（强烈建议）

在一台**已经能正常跑 CUDA 的机器/容器**上做一次，之后所有新部署都秒级完成：

```bash
BUNDLE=/path/to/cuda-bundle
mkdir -p $BUNDLE/{lib64,include,nvvm-lib,bin}

# cublas 动态库（-h 必须加，否则只拷到符号链接）
docker exec AMM sh -c "cd /usr/local/cuda-13.2/lib64 && tar -chf - \
  libcublas.so.13.4.1.3 libcublasLt.so.13.4.1.3 libnvblas.so.13.4.1.3" \
  | tar -xf - -C $BUNDLE/lib64

# cublas 头文件
docker exec AMM sh -c "cd /usr/local/cuda-13.2/include && tar -chf - ." \
  | tar -xf - -C $BUNDLE/include

# nvvm 前端 + 运行库
docker exec AMM sh -c "cd /usr/local/cuda-13.2/nvvm && tar -chf - bin" | tar -xf - -C $BUNDLE
docker exec AMM sh -c "cd /usr/local/cuda-13.2/nvvm/lib64 && tar -chf - ." | tar -xf - -C $BUNDLE/nvvm-lib

# CCCL（多数镜像没有，需从 GitHub 取，约 12MB）
curl -fsSL --http1.1 -o /tmp/cccl.tar.gz \
  https://github.com/NVIDIA/cccl/releases/download/v3.5.0/cccl-src-v3.5.0.tar.gz
mkdir -p $BUNDLE/include/cccl && cd /tmp && tar xzf cccl.tar.gz
DST=$BUNDLE/include/cccl
cp -r cccl-src-v3.5.0/libcudacxx/include/* $DST/
cp -r cccl-src-v3.5.0/cub/cub $DST/cub
cp -r cccl-src-v3.5.0/thrust/thrust $DST/thrust
cp -r cccl-src-v3.5.0/cudax/include/* $DST/
```

然后启动容器时挂上去：

```bash
-v /path/to/cuda-bundle:/opt/cuda-bundle:ro
```

> **关键点**：必须用 `tar -chf`（`-h` 解引用符号链接）。
> 用 `docker cp` 只会得到一堆断掉的链接，看起来文件在、实际加载失败。

### 7.4.4 gcc 版本要求

CUDA 13.x **不支持 gcc 11.5**（Rocky 9 默认），会用
`--gnu_version=110500` 一堆报错让编译器识别失败。

`install.sh` 会自动装 `gcc-toolset-12`。手动编译时记得先启用：

```bash
source /opt/rh/gcc-toolset-12/enable
gcc --version   # 应为 12.x
```

## 7.5 升级

代码目录是挂载的，**改代码不需要重建镜像**：

```bash
cd /path/to/amm/app
git pull origin v1.0        # 或 master（两分支已统一）
docker restart AMM
sleep 20
curl -s http://localhost:60008/api/health
```

生产目录通常有这几处**有意保留**的本地改动，pull 前不要 `checkout .` 掉：

```
M  backend/config/models_config.yaml     # 节点名等运行时配置
?? data/                                 # 运行时数据库
?? templates/custom/                     # 自建模版
```

安全做法：

```bash
git stash -u
git pull origin v1.0 --ff-only
git stash pop
```

> **升级后如果版本号没变**：说明旧进程还在跑，`docker restart AMM` 即可。

## 7.6 Unraid 标准容器（dockerMan）

如果你在 Unraid 上，建议用 dockerMan 容器（Docker 页可见图标、可 UI 启停、可模板重建）。

> 不要用 `docker compose up` —— compose 起的容器没有 Unraid label，
> Docker 页看不到，也无法作为模板重建。

### 7.6.1 构建镜像（推荐用本地 CUDA 包）

| Dockerfile | 何时用 |
|---|---|
| `deploy/Dockerfile.local-cuda` | **默认用这个**，零外网下载 |
| `deploy/Dockerfile.unraid` | 网络极好且无本地组件包时 |

```bash
cd /path/to/amm/deploy
cp ../backend/requirements.txt ./requirements.txt
cp -r /path/to/cuda-bundle ./cuda-bundle     # 见 7.4.3 制作方法
docker build -f Dockerfile.local-cuda -t amm:rocky9-cu132 .
```

⚠️ **不能用 symlink 指向组件包**，`docker build` 不跟随上下文外的符号链接，
会报 `failed to compute cache key: not found`。必须 `cp -r` 成真实目录。

⚠️ **组件包必须包含 `libcudart`**。它和 cublas 是不同包，
只导 cublas 时镜像能构建、服务 health 也绿，但一启动模型就报
`libcudart.so.13: cannot open shared object file`。

### 7.6.2 三个必须的 label

```bash
-l net.unraid.docker.managed=dockerman
-l "net.unraid.docker.icon=https://raw.githubusercontent.com/xztjhs/amm/master/frontend/assets/logo.png"
-l "net.unraid.docker.webui=http://[IP]:[PORT:80]"
```

**图标必须是 raw 直链**：

```
✅ raw.githubusercontent.com/.../logo.png   → image/png
❌ github.com/.../blob/.../logo.png         → text/html（Unraid 拿不到图片）
```

### 7.6.3 启动容器

```bash
docker run -d --name AMM \
  -l net.unraid.docker.managed=dockerman \
  -l "net.unraid.docker.icon=https://raw.githubusercontent.com/xztjhs/amm/master/frontend/assets/logo.png" \
  -l "net.unraid.docker.webui=http://[IP]:[PORT:80]" \
  --restart unless-stopped --runtime nvidia \
  -e NVIDIA_VISIBLE_DEVICES=all -e NVIDIA_DRIVER_CAPABILITIES=compute,utility \
  -e TZ=Asia/Shanghai -e AMM_ROOT=/amm -e MODELS_DIR=/models \
  -e PYTHONPATH=/amm/backend -e AMM_ENGINES_ROOT=/opt/amm-engines \
  -p 60008:80 \
  -v /path/to/amm/app:/amm \
  -v /path/to/models:/models \
  -v /path/to/amm/engines:/opt/amm-engines \
  amm:rocky9-cu132 /bin/bash /amm/deploy/docker-entrypoint.sh
```

> 容器名是 **`AMM`（大写）**。`docker restart amm` 会报 `No such container`。

### 7.6.4 模板

位置：`/boot/config/plugins/dockerMan/templates-user/my-AMM.xml`
仓库副本：`deploy/unraid/my-AMM.xml`（17 个配置项）

改端口/路径/环境变量：先备份模板 → 改 xml → 在 Docker 页点容器 Edit → 应用。

### 7.6.5 验收

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:60008/          # ① 200
curl -s http://127.0.0.1:60008/api/health                                  # ② status ok
docker inspect AMM --format '{{index .Config.Labels "net.unraid.docker.managed"}}'  # ③ dockerman
ss -ltn | grep ":60008 "                                                   # ④ 在监听
```

```bash
curl -s -X POST http://127.0.0.1:60008/api/instances/launch \
  -H 'Content-Type: application/json' \
  -d '{"model_type":"embedding","engine_type":"llama_cpp",
       "model_file":"Qwen/Qwen3-Embedding-0.6B-GGUF/Qwen3-Embedding-0.6B-Q8_0.gguf",
       "parameters":{"embeddings":true},"model_uid":"verify"}'
# 期望 "ready":true

nvidia-smi --query-compute-apps=pid,used_memory --format=csv,noheader
# 必须能看到该进程，否则说明静默退回了 CPU
```

## 7.7 环境变量参考

| 变量 | 默认 | 说明 |
|---|---|---|
| `AMM_ROOT` | `/amm` | 程序与数据根目录 |
| `MODELS_DIR` | `/models` | 模型文件目录 |
| `AMM_ENGINES_ROOT` | `/opt/amm-engines` | 推理引擎安装目录 |
| `PYTHONPATH` | `/amm/backend` | Python 模块搜索路径 |
| `AMM_START_PRELOAD` | `0` | 启动时是否预加载 diffusers 模型 |
| `AMM_AUTO_RELEASE` | `full` | 空闲时释放显存策略 |
| `AMM_LOG_MAX_BYTES` | `52428800` | 单个日志文件上限（50MB） |
| `AMM_LOG_BACKUPS` | `5` | 日志保留份数 |
| `AMM_LAUNCH_READY_TIMEOUT` | `30` | launch 等端口就绪的超时秒数，0=不等 |
| `AMM_FS_ROOTS` | 空 | 文件管理器额外允许的根目录（`:` 分隔） |
| `AMM_CUDA_BUNDLE` | `/opt/cuda-bundle` | CUDA 组件包路径 |
| `HF_HOME` | `/amm/data/huggingface` | HuggingFace 缓存 |
| `MODELSCOPE_CACHE` | `/amm/data/modelscope` | ModelScope 缓存 |

## 7.8 安装耗时参考

| 阶段 | 耗时 |
|---|---|
| 系统依赖 | ~2 分钟 |
| CUDA 组件补齐（有本地包） | ~10 秒 |
| CUDA 组件补齐（无本地包，下载 RPM） | 10+ 分钟，易断流 |
| llama.cpp CUDA 编译（32 核） | ~7 分钟 |
| Python 依赖（已缓存） | ~20 秒 |
| **合计（有 CUDA 包）** | **约 10 分钟** |

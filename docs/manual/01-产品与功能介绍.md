> 版本：v1.9 ｜ 更新日期：2026-11-17

## 1.1 什么是 AMM？

**AMM（AI Models Manage）** 是一套 **AI 模型统一管理与推理调度平台**。它的核心价值是：

> **在一个网页里，统一管理、启动、配置、测试和对外提供所有主流 AI 模型，让"跑模型"像开关一样简单。**

传统方式下，你要跑一个模型需要：

1. 自己装 Python / CUDA / 依赖库，处理版本冲突
2. 查文档、写启动命令、调几十个参数
3. 写脚本验证是否真的跑通，出错自己翻日志
4. 为不同类型（对话、向量、语音、图片、视频）各写一套流程
5. 对外提供 API 时再搭一层网关、做鉴权、算用量

AMM 把这些全部封装成 **可视化网页操作**。你只需要在网页上点几下：
**选模型 → 启动 → 测试 → 配置客户端 base_url**，即可完成。

### 它解决的具体问题

| 痛点 | AMM 的做法 |
|---|---|
| 不同模型要装不同引擎（llama.cpp / vLLM / Diffusers），版本还冲突 | 引擎目录化：一个类别可跑多个引擎版本，互不干扰，网页里装/卸 |
| 启动参数几十个，记不住也不知道该填什么 | 参数表单按「类别 + 引擎」自动生成，带默认值与说明 |
| 模型跑没跑起来、占多少显存、日志在哪，全靠猜 | Dashboard 实时看状态/显存/端口，实例日志一键打开 |
| 多个模型抢 GPU | 端口与显存统一编排，实例独立进程，按需启停 |
| 对外给客户端用时，各家 SDK 写法不一 | 原生 OpenAI 兼容 `/v1/*`，任何客户端改 base_url 即可 |
| 不知道谁在调、调了多少、花了多少钱 | Token Router：虚拟 Key、用量统计、计费报表、调用历史 |

## 1.2 AMM 能管理哪九类模型？

| 类别 | 图标 | 说明 | 典型用途 |
|------|:--:|------|---------|
| **Chat / LLM / VLM** | 💬 | 通用对话、文本生成、视觉语言模型 | 聊天机器人、问答、文本总结、看图说话 |
| **Embedding** | 🧬 | 文本嵌入向量模型 | 语义检索、RAG 向量化、相似度计算 |
| **Reranker** | 📊 | 重排序模型 | RAG 检索结果精排、相关性打分 |
| **ASR** | 🎙️ | 自动语音识别 | 语音转文字 |
| **TTS** | 🔊 | 文字转语音 | 语音合成、朗读 |
| **OCR** | 👁️ | 光学字符识别 | 图片文字识别 |
| **T2I** | 🖼️ | 文生图 | 文字描述生成图片 |
| **T2V** | 🎬 | 文生视频 | 文字描述生成视频 |
| **I2V** | 🖌️ | 图生视频 | 图片生成视频 |

> 九类之外，v1.1 起支持**同类别多实例**：例如同时跑两个 embedding 模型（不同尺寸/精度），
> 每个实例有独立 UID 与端口，客户端按 UID 调用。

## 1.3 支持哪些推理引擎？

| 引擎 | 支持类别 | 构建 | 说明 |
|---|---|---|---|
| **llama.cpp** | chat / embedding / reranker / asr / tts / ocr | cpu / cuda | GGUF 格式，显存占用低，跨平台最好，**最常用** |
| **vLLM** | chat / embedding | cuda only | 高吞吐，适合并发大的场景；显存需求较高 |
| **Diffusers** | image / video | cuda only | 文生图 / 文生视频 / 图生视频 |
| **sentence-transformers** | embedding | cpu / cuda | safetensors 格式的向量模型 |

引擎可在 **Settings → 推理引擎管理** 里在线查询版本、下载、安装、卸载。
llama.cpp 与 sentence-transformers 区分 `cpu` / `cuda` 两种构建，按需装。

## 1.4 九大功能模块

### ① Dashboard（总览）
系统 CPU / 内存 / 磁盘 / 运行时长四张卡，GPU 实时状态（利用率、显存、温度、功耗、
正在运行的进程），以及九个模型实例的状态列表。

### ② Models（模型实例）
三个子页：

- **启动新实例**：类别 → 引擎 → 版本/Flavor → 模型文件 → 参数 → 启动。留空 UID 会自动生成。
- **运行中实例**：查看所有实例的 UID / 名称 / 类型 / 引擎 / 端口 / 状态 / 显存 / 运行时长 / 请求数，可 Start / Stop / Restart / 结束运行 / 另存为模版。
- **模版库**：预置了常用模型的一键部署配置（含引擎、参数、下载源），也可把自己的实例存成模版复用。

### ③ Token Router（对外服务）
- **外部 Provider**：接入 icompify / siliconflow / openai / anthropic 等，填 Key 后自动拉取模型列表
- **可用模型清单**：本地实例 + 外部模型的合并视图，可编辑单价/类型/备注
- **虚拟 API Key**：签发给不同应用，支持 RPM 限流、月度/总量配额、有效期、模型白名单
- **用量报表与计费**：按 Key / 模型统计 tokens 与金额，支持导出 CSV 账单与详单

### ④ Playground（在线测试）
九个页签对应九类模型，选模型 → 填内容 → 点测试，立即看到结果与性能指标（耗时、TTFT、TPS）。

### ⑤ Tools（模型工具）
- 模型自动下载（ModelScope / HuggingFace，支持镜像、断点续传、速度显示）
- GGUF 量化（把 safetensors / fp16 压成 q4_k_m 等）
- vLLM → GGUF 格式转换

### ⑥ Log Center（日志中心）
- **文件日志**：按来源 / 级别 / 关键字过滤，支持导出与清理
- **调用历史（v1.9 增强）**：每次推理的输入、**真实输出文本**、参数、性能指标。
  流式调用也会记录实际生成内容，不再是 `(stream)` 占位符。

### ⑦ GPU Monitor
GPU 详细指标独立页面（v1.9 起有导航入口）。

### ⑧ Settings（设置）
- **服务配置**：只读展示 host / port / 目录 / 版本
- **目录配置（v1.9 新增）**：models / logs / data / templates / verification 五个目录可改
- **项目品牌（v1.9 新增）**：项目名称、副标题、LOGO，改完顶栏 + 浏览器标题栏 + favicon 同步
- **鉴权开关（v1.9 新增）**：一键完全关闭/开启 `/v1/*` 鉴权，带二次确认
- **本地文件管理（v1.9 新增）**：浏览 / 查看 / 编辑 / 新建 / 删除 / 上传 / 下载
- **运维操作**：重载配置、重启服务、下载服务日志
- **推理引擎管理**：版本查询、安装、卸载、任务进度

### ⑨ 用户手册
就是你现在看的这份，右上角 📚 按钮随时打开。

## 1.5 部署形态

| 形态 | 适用场景 |
|---|---|
| **Docker 容器（推荐）** | Unraid / 群晖 / 任意 Linux，一条 `docker run` 起服务 |
| **裸机部署** | 已有 Python 3.11 + CUDA 环境，直接 `bash deploy/install.sh` |

推荐硬件：

- NVIDIA GPU（本环境实测 RTX A5000 24G 可跑 7B 级模型与 embedding）
- 内存 ≥ 32G（跑 27B 以上模型建议 64G）
- 磁盘：模型文件很占地方，建议 ≥ 500G SSD

## 1.6 访问入口

服务启动后，统一用一个端口承接所有功能：

```
http://<服务器IP>:60008/          → WebUI 管理界面
http://<服务器IP>:60008/api/*     → 管理接口（供 WebUI 调用）
http://<服务器IP>:60008/v1/*      → OpenAI 兼容 API（供客户端调用）
```

> 端口以实际部署为准（本环境宿主机映射 60008；官方 compose 默认 60006）。

OpenAI 客户端（Cherry Studio / Open WebUI / Chatbox 等）只需把 base_url 填成
`http://<服务器IP>:<端口>/v1`，API Key 留空或用 Token Router 签发的虚拟 Key。

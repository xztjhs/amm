# 第 1 章 AMM 产品与功能介绍

> 版本：v0.8.0 ｜ 2026-08-09

---

## 1.1 什么是 AMM？

**AMM（AI Models Manage）** 是一套 **AI 模型统一管理与推理调度平台**。它的核心价值是：

> **在一个网页里，统一管理、启动、配置和测试所有主流 AI 模型，让"跑模型"像开关一样简单。**

传统方式下，你要跑一个大模型需要：
1. 自己装 Python / CUDA / 依赖库
2. 编写启动命令行、配置各种参数
3. 写测试脚本验证是否跑通
4. 为不同类型的模型（对话、向量、语音、图片、视频）各写一套流程

AMM 把这些全部封装成 **可视化网页操作**。你只需要在网页上点几下，选模型 → 启动 → 测试，即可完成。

## 1.2 AMM 能管理哪九类模型？

| 类别 | 图标 | 说明 | 典型用途 |
|------|:--:|------|---------|
| **Chat / LLM / VLM** | 💬 | 通用对话、文本生成、视觉语言模型 | 聊天机器人、问答、文本总结 |
| **Embedding** | 🧬 | 文本嵌入向量模型 | 语义检索、RAG 向量化、相似度计算 |
| **ASR** | 🎙️ | 自动语音识别 | 语音转文字 |
| **TTS** | 🔊 | 文字转语音 | 语音合成、朗读 |
| **Reranker** | 📊 | 重排序模型 | RAG 检索结果精排、相关性打分 |
| **OCR** | 👁️ | 光学字符识别 | 图片文字识别 |
| **T2I** | 🖼️ | 文生图 | 文字描述生成图片 |
| **T2V** | 🎬 | 文生视频 | 文字描述生成视频 |
| **I2V** | 🖌️ | 图生视频 | 图片生成视频 |

> 一套系统覆盖 **文本 / 向量 / 语音 / 图像 / 视频** 全模态。

## 1.3 混合推理引擎架构

AMM 支持 **三种主流推理引擎自由切换**，做到"一个平台跑所有模型"：

### llama.cpp（🗼 高性能 GGUF）
- 支持 GGUF 量化模型，CPU/GPU 混合推理
- 覆盖：chat / embedding / asr / tts / reranker / ocr 六类
- 轻量、省显存，适合在任意机器跑

### vLLM（⚡ 高并发）
- PagedAttention / continuous batching，**高并发 LLM 推理**
- 适合 chat / embedding，需要 NVIDIA GPU
- Blackwell (sm_120) 架构已验证通过

### Diffusers（🎨 扩散模型）
- HuggingFace 扩散模型，负责 **图像 / 视频生成**（T2I / T2V / I2V）
- 支持 FP8 量化、显存自动释放、CPU offload

**在 Models 页可为每类模型单独选择引擎**，AMM 自动生成对应的启动命令。

## 1.4 核心功能速览

### ① 模型管理（Dashboard / Models）
- 网页版仪表盘：实时展示 CPU / 内存 / 磁盘 / 运行时长 / **GPU 全维度状态**
- 9 类模型统一启动 / 停止 / 重启，状态一目了然
- 为每类模型选择推理引擎，自动编排启动命令
- 参数可视化编辑（无需手写命令行）

### ② 推理测试（Playground）
- 网页内直接对话（流式输出），实测 TTFT / TPS / 端到端性能
- 支持多模态：上传图片做视觉问答、生成图片、生成视频
- 支持向量、语音、重排、OCR 各类的网页测试

### ③ 模型下载与转换（Tools）
- 从 **ModelScope / HuggingFace** 一键下载模型（支持代理、断点续传、速度显示）
- **GGUF 量化转换**：把模型按精度转换（q4_k_m 等）
- **vLLM → GGUF**：把 Safetensors 转成 llama.cpp 可用的 GGUF

### ④ OpenAI 兼容 API（/v1/*）
- 标准 OpenAI 格式，任何支持 OpenAI API 的工具都能直接接 AMM
- `/v1/chat/completions`（含流式）、`/v1/embeddings`、`/v1/audio/*`、`/v1/ocr`、`/v1/rerank`、`/v1/images/generations`、`/v1/videos/generations`

### ⑤ 运维管理（Settings / Logs）
- 网页重载配置、重启服务、下载日志
- 引擎版本管理（网页安装 / 卸载不同版本的 llama.cpp / vLLM / Diffusers）
- 模型实时日志查看（Auto 跟随）

## 1.5 系统规格（当前部署环境）

| 项目 | 值 |
|------|-----|
| 部署形态 | Docker 容器（AMM 专用），无 Dockerfile，基础镜像 + 安装脚本 |
| 宿主 | Unraid，Docker 容器，NVIDIA RTX 6000D 85.6GB |
| CUDA | 13.2（Blackwell sm_120） |
| 统一入口 | `http://<宿主IP>:<WEB_PORT>/`（WebUI + /api/* + /v1/*） |
| 模型目录 | `/models`（宿主机映射） |
| 项目代码 | `/amm`（宿主 `/mnt/data/docker/app/amm`） |

### 端口规划

| 端口 | 用途 |
|------|------|
| <WEB_PORT> -> 80 | 统一 Web 入口（WebUI + 管理 API + OpenAI API） |
| 60007 -> 443 | HTTPS 预留 |
| 18081-18089 | 推理服务内部端口（chat/embedding/asr/tts/reranker/ocr/t2i/t2v/i2v） |

## 1.6 目录结构

```
amm/
├── backend/          # 后端（Python aiohttp）
│   ├── server.py     # 主服务（WebUI + /api/* + /v1/*）
│   ├── core/         # 核心：模型管理/版本管理/引擎
│   ├── api/          # API：openai_bridge / diffusers_bridge / ...
│   ├── config/       # 配置文件（models_config.yaml 等）
│   └── engines_installed/  # 已安装引擎（vllm/llama_cpp/diffusers）
├── frontend/         # 前端（原生 JS + HTML + CSS）
├── deploy/           # 部署脚本与 docker-compose
├── docs/             # 文档与手册
└── logs/             # 运行日志
```

> 容器配置与部署脚本已抽取为独立仓库 `amm-docker`（见 1.7）。

# AMM Chat/LLM/VLM 引擎参数调优指南

> 来源：本机安装的 vLLM 0.22.1 / llama-server `--help` 实测 + **AKVD 知识库**（vllm-docs 5127 / llamacpp-docs 1265 / diffusers-docs 6615 chunks）检索。
> 知识库检索使用 AKVD CLI：`cd ~/AKVD && python3 -m akvd.cli.main search "<query>" <domain> --limit 5`

## 一、vLLM 关键参数（18 项）

### 并行度
| 参数 | 说明 | 建议 |
|---|---|---|
| `tensor_parallel_size` | 张量并行（单卡切分权重到多卡） | ≤ GPU 数，需 NVLink；RTX 6000D×1 时保持 1 |
| `pipeline_parallel_size` | 流水线并行（按层切分） | 多机/超大模型用；单机一般 1 |
| `data_parallel_size` | 数据并行（多副本各应不同请求） | 需 >1 GPU；单卡 1 |

### 长度 / 显存 / 批处理
| 参数 | 说明（AKVD） | 建议 |
|---|---|---|
| `max_model_len` | 最大上下文（KV 缓存上限） | 显存允许下尽量大；过大占显存 |
| `gpu_memory_utilization` | 用于 KV 缓存的显存比例 | 留 10-15% 余量（如 0.85）；扛峰值防 OOM |
| `max_num_seqs` | 一次调度的最大序列数 | 并发越高越吃显；默认 256 |
| `max_num_batched_tokens` | 单批 token 上限 | **影响首Token(ITL)**；online 默认 2048×world，offline 4096×world |

### 精度 / 量化 / KV
| 参数 | 含义 | 建议 |
|---|---|---|
| `dtype` | 权重+激活精度 | auto/float16/bfloat16 |
| `quantization` | 量化方式 | auto/awq/gptq/fp8/bitsandbytes；按模型原量化 |
| `kv_cache_dtype` | KV 缓存精度 | fp8 可省显存（fp8_e5m2/e4m3） |
| `block_size` | KV Block 大小 | auto/16/32/64 |

### 性能开关
| 参数 | 含义（AKVD） |
|---|---|
| `enable_prefix_caching` | 自动前缀缓存，多轮/共享前缀场景显著提速（V1 由 KV manager 的 Block 实现） |
| `enable_chunked_prefill` | **vLLM V1 默认开启**：把大 prefill 切块与 decode 混合批处理，提升吞吐+时延，优先 decode（降 ITL） |
| `enforce_eager` | 禁用 CUDA graph（触发 CUDA graph 失败时用） |
| `cpu_offload_gb` | 指定权重卸载到 CPU（显存不足时） |
| `served_model_name` | 对外暴露的模型名 |
| `trust_remote_code` | 加载远端代码模型时启用 |

## 二、llama.cpp 关键参数（26 项）

### 资源
- `n_gpu_layers`: 卸载到 GPU 的层数（-1→尽量多，999→全部）
- `threads`: CPU 线程数；`batch_size`/`ubatch_size`: 批量
- `flash_attn`：FlashAttention；`mlock`：锁内存防换页；`mmap`：内存映射（false 走 `--no-mmap`）
- `cache_type_k/v`：KV 缓存类型 f16/q8_0/q4_0（量化省内存，q4 有精度损失）

### 采样
- `temp/top_p/top_k/repeat_penalty/repeat_last_n/min_p`
- Mirostat（模式 0off/1/2，lr 学习率，ent 目标困惑度）
- `frequency/presence_penalty`、`rope_freq_base/scale`

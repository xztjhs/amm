## 0. 速查表

```bash
# 状态
curl -s http://127.0.0.1:60008/api/health          # 健康检查
docker ps --filter name=AMM                         # 容器状态
docker exec AMM ls /opt/amm-engines/llama_cpp/      # 已装引擎

# 最常用
docker restart AMM                                  # 重启服务
cd /path/to/amm && git pull --ff-only origin v1.0   # 升级代码
bash deploy/sync-unraid-template.sh                 # 同步 Unraid 模板
```

> **容器名是大写 `AMM`**。`docker restart amm` 会报 `No such container`。

## 1. 部署形态

```
宿主机 <YOUR_HOST>（Unraid 7.3.2, <HOSTNAME>）
├── 容器 AMM（amm:rocky9-cu132）
│   ├── 镜像 2.24GB，Rocky Linux 9.3 + CUDA 13.2 完整工具链
│   ├── 端口 60008 -> 80
│   └── HEALTHCHECK 每 30s
├── 挂载（宿主 -> 容器）
│   ├── /path/to/amm            -> /amm            （代码+数据+SQLite）
│   ├── /path/to/models -> /models         （模型权重）
│   └── /path/to/amm-engines     -> /opt/amm-engines（推理引擎）
└── 模板 /boot/config/plugins/dockerMan/templates-user/my-AMM.xml
```

**关键点**：代码目录是挂载的，改代码只要 `git pull` + 重启，**不需要重建镜像**。
只有依赖（requirements.txt）或 CUDA 组件变化时才需要重建镜像。

访问：`http://<YOUR_HOST>:60008`

## 2. 日常操作

### 启停重启

```bash
docker stop AMM
docker start AMM
docker restart AMM          # 最常用：改完代码/配置后

# 看是否真的起来了
docker ps --filter name=AMM --format '{{.Status}}'   # 期望 Up xx (healthy)
```

### 看日志

```bash
# 服务日志（主入口，会轮转）
docker exec AMM tail -100 /amm/logs/amm_server.log

# 只关注错误
docker exec AMM tail -200 /amm/logs/amm_server.log | grep -iE "error|exception|traceback"

# stdout（WARNING 以上，量很小）
docker exec AMM tail -50 /amm/logs/amm_server.out

# 访问日志（已过滤健康轮询，只留真实调用）
docker exec AMM tail -30 /amm/logs/access.log
```

> v1.9.2 起日志做了分流：`.out` 只留 WARNING 以上，访问日志独立到 `access.log`，
> 且过滤掉前端 0.5s 轮询。此前 `.out` 每天涨 150MB。

### 查看实例状态

```bash
# 所有实例（含 stopped）
curl -s http://127.0.0.1:60008/api/instances | docker exec -i AMM python3.11 -m json.tool

# 只列运行中的
curl -s http://127.0.0.1:60008/api/running-models
```

## 3. 升级代码

```bash
cd /path/to/amm

# 1) 先看有没有本地改动会被覆盖
git status --short

# 2) 拉取（分支是 v1.0，不是 master）
git pull --ff-only origin v1.0

# 3) 重启生效
docker restart AMM

# 4) 验证
curl -s http://127.0.0.1:60008/api/health
```

### ⚠️ 三个必须知道的事

**① 部署跟的是 `v1.0` 分支，不是 `master`**

开发端改完必须同步两个分支：
```bash
git branch -f v1.0 master && git push origin master v1.0
```
否则部署端拉下来还是旧代码。历史上这两个分支曾相差 94 个 commit。

**② `models_config.yaml` 常有本地改动**

生产环境这个文件会被程序重写（格式变化、加 `node_name` 等），`git pull` 会被挡：

```bash
cp backend/config/models_config.yaml /tmp/models_config.bak-$(date +%Y%m%d-%H%M%S)
git checkout -- backend/config/models_config.yaml
git pull --ff-only origin v1.0
# 然后把需要保留的本地项补回仓库配置并提交
```

**③ 手工拷贝的文件会挡住 pull**

如果之前 `scp` 过文件（如 `deploy/*.sh`），先确认与远端一致再丢弃：
```bash
git diff origin/v1.0 -- deploy/xxx.sh      # 空 = 完全一致
git checkout -- deploy/xxx.sh
```

### 验证升级成功

```bash
# 版本号
curl -s http://127.0.0.1:60008/api/settings | grep -o '"version":"[^"]*"'

# 提交号
cd /path/to/amm && git log --oneline -1
```

## 4. 重建镜像

**什么时候需要**：改 `requirements.txt`、换 CUDA 版本、改 Dockerfile。

```bash
cd /path/to/amm/deploy

# 1) requirements 必须存在（Dockerfile 要 COPY）
cp ../backend/requirements.txt ./requirements.txt

# 2) 构建前先备份当前镜像
docker tag amm:rocky9-cu132 amm:rocky9-cu132-bak-$(date +%Y%m%d-%H%M%S)

# 3) 构建（约 5-10 分钟）
docker build -f Dockerfile.local-cuda -t amm:rocky9-cu132 .

# 4) 重建容器
cd .. && bash deploy/sync-unraid-template.sh --recreate
```

### 构建会自带自检

Dockerfile 里有一层专门验证 CUDA 工具链：
```dockerfile
RUN nvcc --version && \
    printf '__global__ void k(){}\nint main(){k<<<1,1>>>();return 0;}\n' > /tmp/t.cu && \
    nvcc -o /tmp/t /tmp/t.cu
```
**编不过就在构建期失败**，不会等到用户点「安装引擎」才发现。

### 镜像回滚

```bash
docker tag amm:rocky9-cu132-bak-20261118-194242 amm:rocky9-cu132
bash deploy/sync-unraid-template.sh --recreate
```

### cuda-bundle 缺失时

镜像依赖 `deploy/cuda-bundle/`（约 1GB，**不入 git**）。重建前确认它存在：

```bash
du -sh deploy/cuda-bundle     # 期望 ~1GB
```

没有的话从现成容器导出：
```bash
bash deploy/export-cuda-bundle.sh AMM
```

## 5. Unraid 容器管理

### 三个 dockerMan 标签

Unraid Docker 页靠容器标签识别「标准受管容器」。缺失会导致：没图标、
没 WebUI 按钮、不能用界面启停/编辑/重建。

```bash
docker inspect AMM --format '{{json .Config.Labels}}' | python3 -m json.tool
```

| 标签 | 期望值 |
|---|---|
| `net.unraid.docker.managed` | `dockerman` |
| `net.unraid.docker.webui` | `http://[IP]:[PORT:60008]` |
| `net.unraid.docker.icon` | `http://<YOUR_HOST>:60008/assets/logo-128.png` |

### 同步模板

```bash
cd /path/to/amm

bash deploy/sync-unraid-template.sh            # 只更新模板
bash deploy/sync-unraid-template.sh --recreate # 更新并按模板重建容器
```

脚本会：备份旧模板 → **校验 WebUI 端口与端口映射一致** → 重建并注入标签 → 健康检查。

### 改端口/路径/环境变量

改 `deploy/unraid/my-AMM.xml` → 推仓库 → 部署端 `--recreate`。
**不要直接改 `/boot/config/.../my-AMM.xml`**，下次同步会被覆盖。

### 在界面上操作

Unraid → Docker → 找到 AMM → 卡片右侧图标：
- **WebUI**：打开 AMM（端口取自模板 `[PORT:60008]`）
- **Console**：进容器终端
- **Edit**：改配置（等价于改模板）
- **Restart / Stop**：启停

## 6. 引擎管理

### 查看已装

```bash
docker exec AMM ls /opt/amm-engines/llama_cpp/
docker exec AMM ls /opt/amm-engines/           # 所有引擎类型
```

### 版本过滤规则

llama.cpp 的 `b#####` 在 GitHub 上全是 `prerelease`（每天几十个），
官方正式版只有 `vX.Y.Z`。界面默认只显示正式版。

要临时看 pre 版：
```bash
docker inspect AMM --format '{{range .Config.Env}}{{println .}}{{end}}' | grep PRERELEASE
# 没有则在模板加 AMM_ENGINE_INCLUDE_PRERELEASE=1 后重建
```

本地已装的 pre 版仍会显示（标「本地」），可以卸载。

### 装新版本引擎

界面：Settings → 推理引擎管理 → 选版本 → 安装。

命令行：
```bash
curl -s -X POST http://127.0.0.1:60008/api/engines/tasks \
  -H 'Content-Type: application/json' \
  -d '{"engine_type":"llama_cpp","version":"v1.0.0","flavor":"cuda","action":"install"}'

# 查进度
curl -s http://127.0.0.1:60008/api/engines/tasks | docker exec -i AMM python3.11 -m json.tool
```

CUDA 版编译 5-20 分钟。**编译需要完整 CUDA 工具链**（镜像已自带）；
若缺失，`_ensure_cuda_toolchain` 会自动从 NVIDIA 源补齐。

### 验证引擎可用

```bash
# 版本
docker exec AMM /opt/amm-engines/llama_cpp/v1.0.0-cpu/bin/llama-server --version

# 设备识别（cuda 版必须能看到 GPU）
docker exec AMM /opt/amm-engines/llama_cpp/v1.0.0-cuda/bin/llama-server --list-devices
```

## 7. 排障

### 容器起不来

```bash
docker ps -a --filter name=AMM          # 看 ExitCode
docker logs AMM --tail 50               # 看启动日志
```

### 服务 502 / 打不开

```bash
docker exec AMM curl -s localhost/api/health
docker exec AMM tail -50 /amm/logs/amm_server.log
```

### 模型启动失败

```bash
# 从 API 看具体错误（含候选文件建议）
curl -s -X POST http://127.0.0.1:60008/api/instances/<uid>/start

# 常见：「模型文件不存在」→ 配置里的路径与实际不符
docker exec AMM ls /models/amm/ | head
```

### 显存不足

```
ggml_backend_cuda_buffer_type_alloc_buffer: cudaMalloc failed: out of memory
```
24GB 卡上**不要同时跑** ASR + TTS + OCR + Reranker。TTS 单独跑正常。
需要共存时用 CPU flavor（`-ngl 0`）。

### 实例端口连不上（重要）

**实例端口只监听容器网络，宿主机访问不到。**

```bash
# ✗ 错：宿主机上直接 curl
curl http://127.0.0.1:18082/health    # 空响应

# ✓ 对：进容器 curl
docker exec AMM curl -s http://127.0.0.1:18082/health
```

### GPU 不可见

```bash
docker inspect AMM --format '{{.HostConfig.Runtime}}'   # 期望 nvidia
docker exec AMM nvidia-smi | head -10
```

### 磁盘占用异常

```bash
du -sh /path/to/amm/*  | sort -rh | head
du -sh /path/to/amm/logs

# 清 __pycache__（常常几十 MB）
find /path/to/amm -name __pycache__ -type d -prune -exec rm -rf {} +

# 压缩 git（曾从 82M 降到 15M）
cd /path/to/amm && git gc --prune=now
```

## 8. 备份与恢复

### 需要备份的

| 内容 | 路径 | 说明 |
|---|---|---|
| 配置与数据 | `/path/to/amm` | 代码 + `data/amm.db` + 配置 |
| Unraid 模板 | `/boot/config/plugins/dockerMan/templates-user/my-AMM.xml` | 重建容器用 |
| 引擎 | `/path/to/amm-engines` | 可重新安装，可不备 |
| 模型 | `/path/to/models` | 大，可重新下载 |

`deploy/cuda-bundle/` 约 1GB，可用 `export-cuda-bundle.sh` 随时重新生成，不必备份。

### 快速备份

```bash
# 关键配置（不含代码，很小）
tar czf /mnt/<disk>/amm-config-$(date +%Y%m%d).tar.gz \
  -C /path/to/amm \
  backend/config data/amm.db data/router.json 2>/dev/null

# Unraid 模板
cp /boot/config/plugins/dockerMan/templates-user/my-AMM.xml \
   /mnt/<disk>/amm-template-$(date +%Y%m%d).xml
```

### 灾难恢复（容器镜像都没了）

```bash
# 1) 代码（挂载盘还在就直接用；不在则 clone）
cd /path/to
git clone https://github.com/xztjhs/amm.git amm
cd amm && git checkout v1.0

# 2) 重建镜像
cd deploy && cp ../backend/requirements.txt . && \
  docker build -f Dockerfile.local-cuda -t amm:rocky9-cu132 .

# 3) 建容器
cd .. && bash deploy/sync-unraid-template.sh --recreate

# 4) 验证
curl -s http://127.0.0.1:60008/api/health
docker exec AMM ls /opt/amm-engines/llama_cpp/
```

引擎需要重新安装（Settings → 推理引擎管理）。

## 附录：常用 API

```bash
B=http://127.0.0.1:60008

curl -s $B/api/health                    # 健康
curl -s $B/api/system                    # CPU/内存/磁盘/GPU/CPU推理进程
curl -s $B/api/instances                 # 所有实例
curl -s $B/api/running-models            # 运行中实例
curl -s $B/api/settings                  # 配置
curl -s $B/api/engines/catalog           # 引擎版本目录
curl -s $B/api/templates                 # 模版库
curl -s $B/v1/models                     # OpenAI 兼容模型列表
```

启动/停止实例：
```bash
curl -s -X POST $B/api/instances/<uid>/start
curl -s -X POST $B/api/instances/<uid>/stop
curl -s -X POST $B/api/instances/<uid>/restart
```
